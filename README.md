# Visual-eStim-ulator
A web-based estim signal controller for use with the FOC-stim

This is my attempt at creating a real-time, direct controller of the [FOC-stim](https://github.com/diglet48/FOC-Stim) hardware (via [Restim](https://github.com/diglet48/restim)), in order to be able to explore electrode configurations and signals that best match those configurations.

This project was borne from a desire to have a more direct control over the creation of estim signals than what exists out there in the form of Funscripts. While the Funscript ecosystem is large, it seems from my experience that the software out there that converts Funscripts to the Tcode needed to input into Restim, can be really good but sometimes confusing or overwhelming. This is not to belittle that realm, as I have had great success from those Funscript creators and appreciate all of the hard work the community has done so far.  But I wanted something different, where I could lock into a specific signal output/feeling for as long as I wanted, if I wanted, and didn't want to be at the guidance of someone else's pattern sequence. A lot of Funscripts were created with the creators specific electrodes, positions and bodies. Recently I hear several people getting FOC-stim boxes asking "what is the ideal electrode position for Funscript X", or "How do I work the conversion settings on the programs that translate a Funscript to Tcode data?".

To that end, the paradigm of this application foregoes the usage of Funscripts and their format. It relies strictly on creating Tcode parameters at roughly 33ms per entry. Since Restim can be set to look for particular Tcode stream parameters (e.g L0, L1, V0, etc), this application outputs that form of a data stream across a web socket directly to Restim. Thus, creating patterns and sequences for existing videos would need to begin anew. Furthermore, while facets of the application function similarly to audio waveform generation, there is no audio generation at all; it is strictly a data stream that is expected to go directly to Restim. So Stereostim boxes will only work with this if you configure Restim to output to an audio-based stereostim device.  For best results with this, you'll want a FOC-stim hardware device, ideally a v4 (with four outputs) so you can utilize both the 3-phase and 4-phases modes of this application.

With this application, you yourself position the electrodes however you want, for example, a pad on the glans, one on the shaft, and one on the perineum. You yourself decide whether the top pad goes to the "red output" (Channel A), or one of the other colors.  If you want movement that closely resembles "up and down stroking" you wire your electrodes in the combination that achieves that in connection with an output pattern you can devise and control with this application. The application is like a larger expansion of the presets built into Restim, but more flexible and powerful. You can now full explore how various electrode combinations perform to various waveforms/signals very quickly.

This is a pure HTML/JS web application that is currently only optimized for a normal desktop monitor (definitely not mobile optimized). It is heavy JS, but it is all local and doesn't rely on external libraries (like jQuery) at this time. This was geared, and designed, to be run on a local system that can be run without an Internet connection if needed.

This should be considered BETA level software, but I hope it is somewhat refined. It is expected that the user will have some experience with Restim, FOC-stim, and if needed, running their own local web server. Although if anyone wishes to publish this on a public facing URL and provide that to others, that is fine. However, should there be bugs or vulnerabilities that I missed, I am not responsible for consequences of those since again, this has only ever been used (and continues to be used on my end) on a local networked (behind a firewall) web server.

Currently my local web server is in a dockerized container on a Linux system on my own network. However for Windows users, a similar setup can be had for yourself.  I would suggest Googling "setting up an Apache web server in docker on Windows" to start your research. In a nutshell, you'll need to install WSL (Windows subsystem for Linux), then Docker Desktop for Windows. Once that is all going good, I find it easiest to create a Dockerfile to create/run the Apache web server. Once that is good, you'll just need to copy these files into a directory in the web folder of your container.

This is my first take at this, and there will be some rough edges. There will be some facets between the 3-phase and 4-phase decks that are similar, but perhaps worded differently. This is because I began with an audio-based version of this (basically similar to how Electron and other current projects work) and used that as the foundation for the 3-phase facet. Eventually phased out the audio aspects of things, dug into how Restim interpreted incoming 3 and 4 phase signals and built out the 4-phase side.  This was tag-team coded with an AI, but I've known enough about JS since it's inception to hopefully be a good eye and verifier for things it produced. To save time I also utilized it to create more documentation for things. I currently haven't edited it, but at first glance, I think it will be enough to get most self-starters going down the right path.

Very Basic Quick-start

1. Run Restim; this can be locally or on another computer on your network
2. Check in the Preferences->Network what it's web socket URL is; generally it'll be something like - ws:\\localhost:12346\tcode
3. Check in Preference->Tcode that you allow the following Tcode inputs:  L0, L1, V0, C0, P0, P1, P2, P3, e1, e2, e3, e4.  I think these are all in Restim by default and have the corresponding types they are (e.g. V0 = Volume). If not, I'll revise this to include a proper mapping
4. Go to your localhost/host IP and port that was setup for your local web server. If you decide to put this on a domain on the Internet, go there.
5. You can ignore the "video" and "preset" sections for now
6. Choose whether your FOC-stim is looking for a 3-phase or 4-phase data stream by loading an appropriate deck (3 phase is using 3 electrode; 4 phase, 4 electrodes)
7. Choose a web socket destination from the "Connection" area drop-down. You are freely able to change the IP address/port/URL in that field to match what Restim is looking for. When you click connect, it should minimize and turn green saying "Connected"
8. Wire up your electrodes and connect to the FOC-stim and power up the device; make sure everything is recognized in Restim. Go ahead and start the connection between Restim and the FOC-stim.
9. Without turning up the volume on the hardware, go ahead and start "start" the deck you have loaded. You should see the application tracing an output path in your web browser, lighting up the electrode areas as signal strength them increases. You should see the same corresponding movement in Restim as well. So if you have a circular clockwise movement at the maximum radius in the web app, you should see the same in Restim.
10. Try adjusting the volume up and down and you should see the relative volume percentage in Restim change. Adjust the "orbit radius" slider back and forth, and you should see the orbit pattern in Restim shrink toward the center and/or move toward the outer edge.
11. Adjusting the "orbit speed" will make the "power dot" spin faster or slower.
12. Keep a basic clockwise circular pattern at full volume in the application, and slowly turn up the power on your FOC-stim, until you reach your desired level of sensation. Let things settle a bit, since the FOC-stim will change current flow based on the changing of skin resistance over time. Don't turn things up too fast.
13. Once you can feel the pattern across your electrode, start exploring the other controls. Various controls may accomplish similar things, but in slightly different ways; some add in new motion capabilities.
14. Go "slow and low" until you yourself develop an understanding how the application/Restim/FOC-stim/electrodes all work together for you. This can be slightly different for everyone.
15. If you have two FOC-stim's, you can load a second deck, and configure that for the electrodes connected to it.


There are other "ai-generated" documentation files on here, which offer a more in-depth guide on all of the facets of this application. I leave a lot to your own imagination and allow people to provide feedback on things. I'm not guaranteeing I'll be taking requests and adding features, but I am curious to see if this helps people gain a better understanding of their new hardware and how to better make it work for them. I do realize that, yes, this takes some of the "immersion" out of sensations when you need to focus on fiddling with dials while trying to remain aroused.  There are "advanced" features like being able to load a video into the web browser and, somewhat basically, allow either auditory beats or movement on screen (beatmeter), rudimentary control the speed of any loaded deck. You can save a deck configuration either to a JSON file to load in later, or save it to internal web browser memory. If done the later way, those "preset banks" can be loaded onto a basic video timeline (after loading a video); this allows you to take your favorite settings and place them at specific times in a video to get the feel you want, when you want. I hope this gives more people greater insight into the work that current creators go through to produce what they do. But, perhaps it gives those creators a new framework to test out electrodes and signal combinations, and create new content to used through this application. It isn't "pretty", but you can save off your Preset Bank and created Timelines so you can load them up in another web browser.

This has been tested and developed primarily in Chrome, but additional testing has been done in Firefox. In fact FF may be more preferred because Chrome's architecture does not allow the video sounds to be played back without "Creative trickery" that I didn't want to go through. So if you want to hear your video and only use Chrome, you'll need to play your video in VLC or similar external program.
